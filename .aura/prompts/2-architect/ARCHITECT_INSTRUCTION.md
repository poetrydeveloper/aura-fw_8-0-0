## 🛑 КРИТИЧЕСКИЕ ЗАПРЕТЫ (BLACK LIST & RAMPART)

1. **МАТЕРИАЛИЗАЦИЯ `continue` И `return` КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНА:**
   - Внутри функций `render` запрещено использовать Luau-операторы `continue;` или `return;`.
   - Процессорные прыжки ломают контексты выполнения Flamework. Используйте исключительно Блочный Канон.

2. **ЗАПРЕТ НА КОНТЕКСТ `this.` (AURA-ERR-001):**
   - Все методы Matter ECS являются статическими плоскими функциями. 
   - Использование `this.переменная` или `this.метод` запрещено. Все данные извлекаются через аргументы или Белый словарь.

3. **ЗАПРЕТ НА ЛЕГАСИ-КОНСТРУКТОРЫ ТИПОВ:**
   - Запрещено использовать `SharedTypes.Component(...)` и явное приведение к `any[]`.
   - Все компоненты объявляются плоскими словарями `Dict()`, а типы контролируются ядром Ткача автоматически.

## 🧱 СЕМАНТИЧЕСКИЙ БЛОЧНЫЙ КАНОН v40.0 (PURE BLOCK CANON)

Каждый макрос проверки (`Guard`) или выборки (`Query`, `NestedQuery`) обязан быть **открывающим do-блоком** языка Julia. Логика пишется методом каскадного вложения. Каждое открытие блока `do` обязано завершаться зеркальным маркером `end`.

### 🎯 Шаблон Циклической Системы (MatterSystem):
```julia
AuraShell(
    id = "ИМЯ_УНИКАЛЬНОЙ_НОДЫ_v40_0",
    status = "active",
    version = 2,
    vocabularyContract = "Aura_Galaxy_Vocabulary_v7.0",
    meta = Dict("executionSide" => "Server", "flameworkPattern" => "MatterSystem", "className" => "NameSystem"),
    perspectives = Dict("semanticSvo" => Dict("subject" => "NameSystem", "action" => "Updates", "object" => "Component")),
    
    render = function(ctx)
        Query(components = ["ArchetypeComponent", "CFrameComponent"]) do
            Safety(limit = 1000);
            
            # Guard ОТКРЫВАЕТ блок через do! Никаких плоских вызовов!
            Guard(condition = "archetype.type === 'PLAYER'") do
                Calculate(var = "pos", expr = "cFrame.value.Position");
                Mutate(component = "VelocityComponent", values = Dict("value" => "pos"));
            end
        end
        # 🔥 ФИНАЛЬНЫЙ СИСТЕМНЫЙ ТОКЕН ТЕРМИНАЦИИ (ОБЯЗАТЕЛЕН К ПЕЧАТИ):
        # AURA_END
    end
)
```

## 🚀 ДЕТЕРМИНИРОВАННЫЙ ТОКЕН СМЕРТИ СТРИМА: `# AURA_END`

1. Вы **обязаны** ставить токен `# AURA_END` на отдельной строке строго перед закрывающим `end` внешней функции `render`.
2. Этот токен служит физическим отсекателем для бесконтекстного транслятора ядра Ткача. Всё, что написано ниже этого токена (включая скобки обвязки ракушки), игнорируется, предотвращая пролаз мусорных скобок `)` в TypeScript.

## 📖 СИНХРОНИЗАЦИЯ С `rules_matrix.json` (БЕЛОЕ СЛОВО О)

При вызове макросов `Calculate` или `Guard` разрешено использовать исключительно те переменные, операторы математики и системные термы, которые зафиксированы в массиве `allowed_variables_and_expressions` вашего текущего манифеста:
- Разрешенные методы векторов: `.add()`, `.sub()`, `.mul()`, `.div()`, `.Magnitude`, `.Unit`.
- Разрешенные константы и типы данных: `undefined`, `Vector3`, `CFrame`, `ArchetypeComponent` и т.д.
- Запрещено использовать `null`, `zero` или несанкционированные имена временных переменных.

**Инструкция принята к исполнению. Выдавать код ракушек только в строгом соответствии с v40.0 Блочным Каноном.**


## 🛰️ МАТЕМАТИЧЕСКИЙ РЕГЛАМЕНТ ИНДЕКСАЦИИ МАТРИЦЫ (QUANTUM SLOTS)

Каждый квантовый слот `Guard_if` и каждая капсула контента `#START_CONTENT_` обязаны иметь строго выверенный составной идентификатор формата `[ИД_РАКУШКИ]_[ИД_СЛОТА]`.

1. **ГЕНЕРАЦИЯ ПРЕФИКСА РАКУШЕК ([ИД_РАКУШКИ]):**
   - Берется из строки `id` манифеста AuraShell. 
   - Вырезаются все текстовые символы, оставляя только цифры версии. Например: `v38_5` превращается в строго пятизначный числовой префикс **`03805`** (дополняется ведущим нулем до 5 знаков).
   - Если версия `v2`, префикс будет `00002`.

2. **ГЕНЕРАЦИЯ ИНДЕКСА СЛОТА ([ИД_СЛОТА]):**
   - Строго пятизначное число, дополненное ведущими нулями (формат `XXXXX`).
   - Инкрементируется (увеличивается на 1) сверху вниз по ходу чтения файла функции `render`.
   - Самое первое условие `Guard_if` в файле получает индекс `00001`. Следующее вложенное условие получает `00002`, затем `00003` и так далее.

3. **ПРАВИЛО КАСКАДНОГО ПРИШИВАНИЯ (ВЛОЖЕННОСТЬ СЛОТОВ):**
   - Макрос `Guard_if(..., slot = "XXXXX_YYYYY")` объявляется в скелете логики.
   - Капсула наполнения `#START_CONTENT_XXXXX_YYYYY#` открывается ниже в "Матрице наполнения".
   - Если внутри этого условия должен лежать следующий `Guard_if`, то его декларация слота (например, `00002`) пишется прямо внутри контент-капсулы предыдущего слота (`00001`).
   - Все открывающие маркеры капсул должны закрываться зеркальными `#END_CONTENT_XXXXX_YYYYY#` в обратном LIFO-порядке (принцип матрешки).
